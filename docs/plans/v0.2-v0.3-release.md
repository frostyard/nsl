# Plan: Distribution support and verified image delivery releases

Deliver the requested two milestones in order: tag `v0.2.0` after the major distribution profiles work, then tag `v0.3.0` after all supported images are public on GHCR and nsl can verify, pull and run them.

## Phase 1 — v0.2.0 distribution support

All seven profile acceptance suites passed on Snow Linux x86-64. See the [distribution matrix](distribution-support.md) and linked reports for exact image hashes and the distinction between reinstalls and a kernel-version upgrade. [v0.2.0](https://github.com/frostyard/nsl/releases/tag/v0.2.0) is published; CI, release builds, archive checksums and provenance verification passed.

- Validate Debian 13, Ubuntu 24.04 LTS, Fedora 44, CentOS Stream 10, openSUSE Leap 16, openSUSE Tumbleweed and Arch Linux on x86-64. Record exact package inventories and immutable build identities for rolling distributions.
- Require the shared distribution acceptance suite for every profile: fresh identities, execution/PTY, project ownership, networking, two-VM isolation, recovery, rootless containers, package/kernel maintenance, backup/restore, disk growth and removal.
- Preserve native security policy and test it explicitly. Report kernel reinstallation separately from a kernel-version upgrade.
- Publish support evidence and limitations, run `make ci`, commit/push and verify the release workflow for the `v0.2.0` tag.
- **Done when:** every listed profile has passing real VM evidence and the release exists. Profile files or a successful image build alone do not establish support.

## Phase 2 — v0.3.0 image delivery

All seven signed images are public on GHCR. Anonymous fresh-cache pulls and two-VM identity/persistence checks passed for every image; catalogue refresh also passed. See [exact artifacts and measurements](public-image-delivery.md). [v0.3.0](https://github.com/frostyard/nsl/releases/tag/v0.3.0) is published. Tagged-source CI, both archive checksums and GitHub provenance verification passed. The downloaded amd64 release binary also pulled, booted and restarted Debian from a separate empty cache; the guest data persisted. Both requested release milestones are complete.

- Implement the [signed image delivery plan](image-distribution.md), including publisher identity, catalogue freshness/rollback rules, protocol compatibility, bounded resumable downloads and atomic verified caching.
- Build and test all supported images in the publication workflow. Publish the tested artifacts, package inventories, provenance and signatures to public GHCR; promote only passing digests.
- Verify anonymous downloads and actual CLI creation/start/exec from catalogue selections, including a clean cache. Exercise corrupt inputs and interrupted transfers without publishing unverified images or creating environments.
- Run `make ci`, commit/push, tag `v0.3.0` and verify the release workflow.
- **Done when:** all supported images are publicly available and the released CLI can verify, pull and run them.

## Later / ideas

Additional architectures need real hardware validation. SLE needs an authorized source and redistribution research; AlmaLinux and Rocky need their own artifacts and acceptance evidence. Neither inherited recipes nor an amd64/arm64 CLI build imply guest support.
