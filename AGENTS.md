# frostyard/nsl

nsl is a Go CLI for WSL-style Linux machines on atomic Linux hosts: systemd-nspawn containers in one systemd-vmspawn/QEMU VM, from signed Frostyard machine images ([ADR-0016](docs/adr/0016-wsl-style-machines.md), [ADR-0017](docs/adr/0017-shared-vm-and-machine-images.md)). The [implementation plan](https://github.com/frostyard/nsl/blob/e617966e80f6534aa6525f016def59ab58c1d864/docs/plans/shared-vm-implementation.md), now in git history, records how it was built and what each phase proved; [the lifecycle design](docs/design/lifecycle.md#requirements-that-must-not-regress) keeps the requirements it carried. Start at [docs/README.md](docs/README.md); user documentation is the [site](site/content/index.md), and [README.md](README.md) is its short entry.

This is the canonical agent instruction file. `CLAUDE.md`, `GEMINI.md`, `.cursorrules` and `.github/copilot-instructions.md` link here; `.claude/skills` links to `.agents/skills` ([ADR-0002](docs/adr/0002-agent-portable-instruction-surface.md)). Edit the canonical targets only.

## Live code conventions

- The root `main.go` owns command parsing. `state.go` keeps the VM records (the shared VM and each isolated machine's), `vm.go` launches the VM and checks readiness through the agent, `storage.go` handles the data disk, `update` and `list`, `machines.go` the machine records, commands and directory translation, `archive.go` export and import, `apps.go` the host menu entries of `nsl app`, `ports.go` the port forwarder, `desktop.go` desktop sessions and the `nsl-open` broker, and `remote.go` `ssh-config` and `logs`. `image_*.go` verify and cache signed catalogue images. `config.go` reads `nsl.conf`. The `runner` interface abstracts local tools.
- `cmd/nsl-agent` is the VM agent: the forced SSH command, the machine operations, the VM's boot services and its idle monitor. `internal/protocol` holds the request types and validation both ends share. `image/vm/` is the VM image layer and `image/machines/` the machine images.
- Tests use fake runners, fake systemd and local processes; do not require root or a VM for unit tests. A test that needs a file mode sets it with chmod, because the umask reduces a create mode. Language and dependency changes are allowed when justified.
- The specs describe the target system: the [CLI](docs/specs/cli.md), [agent protocol](docs/specs/agent.md), [VM image](docs/specs/vm-image.md), [machine images](docs/specs/machine-images.md) and [image delivery](docs/specs/image-delivery.md). Keep the [requirements that must not regress](docs/design/lifecycle.md#requirements-that-must-not-regress). New work that needs phases gets a plan in `docs/plans/` from its `TEMPLATE.md`, and records its integration evidence there, or in the pull request when no plan covers it. Recorded findings state only what that evidence shows; a fact from elsewhere, such as upstream source, names its source and version, and an untested rule says it is untested.
- Signed image delivery uses `sigstore-go` and bounded zstd under [ADR-0015](docs/adr/0015-image-verification-and-catalogue-policy.md). Keep publisher identity, trust root, rollback/freshness and cache checks intact. Public image artifacts must exclude private VM evidence and archives; follow [the publication design](docs/design/image-publication.md).
- Pass commands as argument arrays (`exec.Command`, and `ExecStartEx` in the agent), never as a shell command line on the host or guest. Validate ownership and permissions of state files (`privateFile`, `checkPrivateDir`) and unit descriptions before changing state. Never overwrite preexisting images, machines, archives or files. Reserve `--root` for explicit administrative commands.
- Storage and archives follow [ADR-0008](docs/adr/0008-offline-storage-management.md) and [ADR-0006](docs/adr/0006-stopped-vm-backups.md): stopped units only, resumable removal and growth, no shrinking, and validation before publishing. Lifecycle calls must reject a replacement ID after waiting for a lock. Never take a trust tier or host share from an archive.
- Keep the host CLI and the agent independent of guest distribution. Distro differences belong in image adapters under the [machine-image contract](docs/specs/machine-images.md) ([ADR-0009](docs/adr/0009-distribution-neutral-guest-contract.md)).
- Regenerate `THIRD_PARTY_NOTICES.txt` with `python3 scripts/license-notices.py` when Go dependencies change; CI checks it against shipped packages.
- Run `make ci` before claiming a change is complete. CI runs the same recipe. It is the last of the gate triad (frostyard/core ADR-0043, ADR-0044): `make verify` is credential-free and leaves a clean checkout clean (module tidiness, license notices, vet, formatting, the pinned golangci-lint, the template gate, script and unit tests), `make check` formats and then verifies, and `make ci` adds the append-only check of `.memory/corrections.jsonl` against `BASE` (CI passes the pull request's base), race-enabled tests with coverage under umask 0077 and the cross builds. `mise install` provides the pinned linter and Node; fix a finding rather than loosening `.golangci.yml`. Never replace, rebuild or reinstall a shared tool binary on the host (a mise install, `~/go/bin`) to make a gate pass: `make lint-version-check` checks the official release that `mise.toml` and `mise.lock` pin, and CI installs that same release, so a local substitute hides a CI failure. When a tool does not match its pin, run `mise install` and report the mismatch. GoReleaser Pro (not OSS) validates `.goreleaser.yaml` in CI using the org secret; run Pro's `goreleaser check` when changing release configuration.
- The template gate (`make verify-template`, from bketelsen/agentic-template) checks the instruction aliases, that every document under `docs/` is linked from `docs/README.md`, `.github/risk-paths.json` and the corrections file. `scripts/check-template.mjs`, `scripts/check-corrections.mjs`, `scripts/lib/risk-paths.mjs` and `test/check-template.test.mjs` are byte-identical copies: change them in the template, then copy them.

## Review, risk and corrections

The repository follows frostyard/core's [repository baseline](https://github.com/frostyard/core/blob/main/docs/specs/repository-baseline.md) ([ADR-0024](docs/adr/0024-adopt-the-repository-baseline.md)); [docs/org-adrs.md](docs/org-adrs.md) lists the core ADRs that bind it.

- A pull request declares its risk tier in the template's `Risk tier` section. A change made for a security advisory, a dependency bump included, is tier 3 even when nsl does not call the affected code. The `PR triage` caller (`.github/workflows/risk-paths.yml`, core's `pr-triage.yml`) gives every pull request 1 level label, `level:L1` to `level:L4`, from `.github/risk-paths.json` at the base, and `risk:high` when the level is L1 or L2; the body of an L1 or L2 pull request names each matched path and why the change is safe. A new release, publication, signing, verification, agent or destructive path gets an entry in the same change, with its level `L1` or `L2` and a `why` that starts with a category of core's [risk-paths spec](https://github.com/frostyard/core/blob/main/docs/specs/risk-paths.md); a smaller change that earns its own entry gets level `L3` or `L4` and a free-text `why`.
- When a review finds a blocking point, the fix adds a guard: a test that fails without the fix, or a rule here when no test can catch it, and 1 line in `.memory/corrections.jsonl` ([.memory/README.md](.memory/README.md)). The file is append-only.
- `README.md` is a `tool` README under core's [README spec](https://github.com/frostyard/core/blob/main/docs/specs/readme.md); keep guides and reference on the site.

## Repository boundary

Never commit binaries, `build/`, `dist/`, `site/dist/`, coverage artifacts, local agent state, credentials or a host-specific VM image. The CLI does not install host packages, change device permissions or sudoers, or share D-Bus, GPU or SSH sockets. Host storage is shared only through the `/mnt/host` allowlist in [ADR-0016](docs/adr/0016-wsl-style-machines.md). Releases are built from `v*` tags by `.github/workflows/release.yml` using GoReleaser Pro and GitHub provenance attestations. Tag one with `make bump`: on a clean `main` that matches `origin/main`, it runs `make ci`, tags the version `svu next` derives from conventional commits (`.svu.yml`), and pushes the tag. Conventional commit subjects therefore set the version and make the release changelog readable. Tools are pinned in `mise.toml` with a committed `mise.lock` (frostyard/core ADR-0043); `mise install` provides them. `go.mod` is the only Go pin, a full `1.x.y` in its `go` directive: `setup-go` reads it in CI, and mise reads it through `idiomatic_version_file_enable_tools = ["go"]`. Never pin Go in `mise.toml`; `scripts/test_go_pin.py` fails when it does, or when the Go checksums in `mise.lock` describe another release than `go.mod`. A Go bump changes `go.mod` and then runs `mise lock`.

## Releases and dependencies

- Tag format: `v0.13.0` (one `v*` series; `.svu.yml` sets the prefix and keeps `v0`).
- How a release starts: a `v*` tag push runs `.github/workflows/release.yml` (GoReleaser Pro, provenance attestations, the Homebrew tap pull request).
- Who tags: a maintainer, with `make bump`. Agents never tag, push tags or release.
- Version rule: `svu next` from Conventional Commit subjects.
- Internal dependencies: `github.com/frostyard/std` in `go.mod`.
- Who uses this repository: frostyard/igloo calls the `nsl` CLI and follows its interface.

Start new documents from the category's `TEMPLATE.md`; update the index and link related docs in both directions. Change site pages in the same change as the behavior they describe, and run `make site` when they change; it builds in strict mode. Rewrite ADRs, specs, plans and code in place when decisions change.
